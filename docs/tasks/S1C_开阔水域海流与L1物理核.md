## 2. 状态、单位与海流接口

固定NED，z向下；位置米、时间秒、姿态弧度、体轴线速度m/s、角速度rad/s、转速rpm。
`nu`明确为对地速度在体坐标系的表达，不是对水相对速度。

推荐纯查询接口（允许等价设计，须说明）：

```python
sample(position_ned_m, time_s) -> CurrentSample
```

返回：
- `velocity_ned_mps`: (3,)
- `jacobian_per_s`: (3,3)，J[i,j]=∂c_i/∂p_j，不得转置混用；
- `partial_t_mps2`: (3,)，固定NED空间点的时间偏导；
- `field_id/version/config_hash/purpose`。

输入输出必须有限，禁止bool冒充标量、形状错误和NaN/Inf；复制外部数组，保证无别名污染。查询不得消费RNG、修改时间或更新艇体。参数化场若需随机相位，只能在构造时用独立种子生成，再将实际参数完整冻结。

首批场：
1. ZeroCurrent：c=0、J=0、∂tc=0。
2. UniformCurrent：常向量c=b；J=0、∂tc=0。导航诊断先用水平流，接口不得把体轴竖向分量硬设为0。
3. SinusoidalUniformCurrent：c=b+a sin(ω_f t+φ_f)，J=0、∂tc=a ω_f cos(ω_f t+φ_f)。ω_f单位rad/s。
4. AffineManufacturedCurrent：c=b+A(p-p0)+d(t-t0)，J=A、∂tc=d；purpose必须为`manufactured_derivative_test`。它仅用于导数验证，不能未经物理假设审查当成真实海域流场或训练环境。

常量流和正弦流是开阔水域工程诊断；本轮不宣称模拟流体压力、波浪或涡量载荷。

## 3. 海流运动学推导与实现

令R=Rz(ψ)Ry(θ)Rx(φ)为体轴到NED旋转，ω为体轴角速度，S(ω)v=ω×v。

(1) p_dot = R nu_linear。
(2) c_body = R.T @ c_ned。
(3) nu_current = [c_body,0,0,0]，nu_relative = nu - nu_current。
(4) c_body_dot = -S(ω)c_body + R.T(∂tc_ned + J_current @ p_dot)。

推导必须写清：R_dot=R S(ω)，故(R.T)_dot=-S(ω)R.T；再对c(p(t),t)求全导数。

注意：
- 这里是沿艇轨迹的导数，不是流体质点加速度。乘J的是p_dot=R nu_linear，不是c_ned，也不是R nu_relative_linear。
- 即使NED海流只有水平分量，艇体倾斜后c_body一般有三维分量。
- NED恒定流的时间/空间偏导为零，但艇体转动时c_body_dot一般不为零。
- 对地速度积分不得额外加c_ned；只有明确改成相对速度状态的另一模型才需要对应运动学变换，本轮不这样改。
- 工程模型忽略环境角速度流、额外流体压力梯度/波浪载荷；写为假设，不写为完整真实海流物理。

## 4. L0/L1分离和连续右端

### 4.1 命名防止重复计算

源码`tau_sum`已扣除了C、D和g。新的L1必须用不含这些扣除项的载荷变量，例如：

F_applied = tau_prop_fin + tau_lift_drag + tau_crossflow。

后面的C、D、g各计一次，不能把旧tau_sum直接当成F_applied再扣一次。

### 4.2 采用原正式方案的L1工程模型

M = M_RB + M_A。

M_RB nu_dot + C_RB(nu)nu
+ M_A(nu_dot - nu_current_dot)
+ C_A_red(nu_relative)nu_relative
+ D(nu_relative)nu_relative + g(eta)
= F_applied。

收集nu_dot并移项：

M nu_dot = F_applied
- C_RB(nu)nu
- C_A_red(nu_relative)nu_relative
- D(nu_relative)nu_relative
- g(eta)
+ M_A nu_current_dot。

使用`solve(M, rhs)`或等价稳定线性求解，不新增随意的质量矩阵逆。

这是原方案约定的半经验研究模型，额外环境压力梯度/波浪载荷暂置零。Fossen公开材料用于核对坐标、速度和矩阵约定，不据此声称所有忽略项在自然海域都为零。

### 4.3 保持与记录

- 参数从固定来源生成，导出质量、惯量、MRB、MA、恢复力、阻尼和执行器界。
- 质量按代码公式约31.0293849758kg，不用旧注释31.9kg覆盖。
- C_RB用nu，C_A用nu_relative；保留源代码附加质量C矩阵中明确置零的对称位置对，记录索引，不称为完整水动力耦合。
- 推进/舵面/升阻/横流项的几何参数和符号沿用冻结模型；不同时引入新推进模型或改变K_prop/10。
- 稳态有流时L0/L1本来可能不同；报告差异，不调阻尼去强行贴合。
- 无流时、同状态和界内实际执行器下，连续nu_dot应与冻结动力学的独立右端对照一致。只对连续右端比较，不要求新执行器积分下200秒轨迹与L0完全相同。

### 4.4 独立期望

可在测试中复制输入、调用冻结Euler动力学一次，用(ν_next-ν)/h取得原连续右端；该步骤仅作数值对照，记录差商舍入误差。L1正式实现不能通过运行旧一步再补丁式调整状态来伪装完整右端。

对动量恒等式另用独立矩阵装配计算残差；保存各六维力/力矩项。不要只在同一个函数里写出表达式再证明自己等于自己。

## 5. 执行器解析更新与步时序

原方案要求先限幅命令，再更新实际执行器：
q_cmd = clip(q_raw, q_min, q_max)
q_next = q_cmd + (q_actual - q_cmd)*exp(-dt/T)。

- q_actual在艇体右端计算中使用，不能替换为q_cmd或尚未到达的q_next。
- 尾舵/艉舵±15°、螺旋桨0到1525rpm（主线正向推进）；T沿用0.1s和1.0s。
- 初始实际执行器越界应拒绝，不偷偷裁回。合法初态和限幅命令下，应由凸组合保证后续不越界。
- T<=0、非有限dt或命令非法时不提交。
- 原控制器增益不调整，七项内部记忆完整保存。

固定首版时序：
1. 从当前状态读取控制器，得到本步raw命令并更新候选控制记忆。
2. 对命令限幅；读取时刻t_k的海流与当前实际执行器。
3. 用L1右端计算nu_dot，nu_next=nu_k+dt*nu_dot。
4. 保持已登记的半隐式Euler时序：eta_next=eta_k+dt*J_kin(eta_k)*nu_next。
5. 用解析式更新实际执行器到q_next。
6. 完成有限值/姿态边界/完整快照校验后统一提交。

这是一阶数值方法，不叫整个系统解析解或高阶积分。若另选积分器，先提交明确方案与对照，不静默替换。

L0仍使用原先更新方式并通过原回归。L1使用新model_id，例如`remus100-l1-openwater-v1`，每条记录含model_id、dt、场哈希和参数哈希。

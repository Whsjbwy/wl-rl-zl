## 3. 按顺序执行

### 3.1 预检查

检查目标目录和 origin、当前分支、已有文件、未提交工作、Git 身份及写权限。保存不含凭据的状态摘要。不修改全局 Git 身份，不删除已有文件来制造干净工作区。

建立任务分支；若运行环境已经生成 Codex 任务分支，沿用并记录。无法推送不阻止无副作用的本地检查，但必须在最终报告明确未上传。

### 3.2 迁入与来源登记

按映射迁入，生成 `docs/provenance/source_manifest.json`，记录来源 URL、源 SHA、上游 SHA、迁入时间、源路径、目标路径、源 blob SHA、文件 SHA-256 和大小。

保留第三方许可。重写新仓库 README 时说明“本仓库为研究开发仓库，基线来自固定源提交”；不要把上游代码称为原创。不要写“已经实现强化学习”或复制尚未运行的成功声明。

### 3.3 保留已验证环境

使用 Python 3.12 的独立虚拟环境，从根目录安装原 `requirements-lock.txt`。不要覆盖用户已跑通的旧仓库虚拟环境。

安装失败或版本不可获得时，保存完整错误与退出码，状态为 BLOCKED。需要兼容依赖方案时单独提出并另存锁文件，不擅自改旧锁再声称精确复现。

记录解释器完整版本、操作系统、依赖实际版本、CPU、可获得的 GPU 信息。只采集相关元数据，不上传完整环境变量或个人目录。

### 3.4 新增一键 S0 验收入口

实现 `scripts/verify_s0.py`，由 Python 入口管理子进程、日志与退出码，支持唯一运行目录，避免 Windows Shell 管道吞掉失败状态。

这是一项待实现任务，不是当前约束包已经提供的脚本。入口负责：来源哈希检查、指定 pytest、默认回归、结果结构与数值检查、依赖检查、生成阶段报告。任一必需项失败必须返回非零退出码。

冻结入口会向其所在根目录的 `results/remus100/` 写入。验收脚本应选择隔离工作副本等方式避免覆盖历史；不得仅改变 cwd 就假定已隔离，因为原代码根据 `__file__` 定位输出。执行时记录实际导入的仿真器模块路径，排除误用另一环境安装的同名包。

可以为新脚本增加必要的依赖/静态配置，但不要直接修改 frozen 锁。为错误传播、缺失文件、错误数值和重复运行目录增加真实测试；不得用写死“PASS”的报告代替执行。

### 3.5 执行指定上游测试

在迁入完成且基线环境可用后，按旧 README 的节点执行：

```powershell
$env:MPLBACKEND = 'Agg'
$Py = '.\.venv\Scripts\python.exe'
& $Py -m pytest `
  PythonVehicleSimulator/tests/test_propeller_advance_speed.py `
  PythonVehicleSimulator/tests/test_crossflow_drag.py `
  PythonVehicleSimulator/tests/test_simulate.py::test_remus100 -q
# 立即读取并记录 $LASTEXITCODE；非零时停止后续成功判定。
& $Py -m pip check
```

上游 README 报告这组节点共 4 个测试，依赖检查是另一个命令。以实际收集结果为准；数量不一致需解释，不能只搜索输出中有没有 passed。

以上是实际源码入口，不代表本次文档制作已经执行它们。若启用更大范围的上游测试，出现既有失败也要单列，不伪造“全套测试通过”。
